## 二、原生可解释性审查（J-Space × J-Lens × SAE）

### 2.1 J-Space 审查：三区结构在 14 层中是否成立

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  J-Space 要求:                                                          │
│  ├── 感知区→工作空间→动作区的边界必须清晰可检测                       │
│  ├── 工作空间必须是低维稀疏瓶颈                                       │
│  ├── 消融工作空间应导致复杂推理崩塌但简单任务不受影响                  │
│  └── 区间信息流方向必须可追踪                                          │
│                                                                         │
│  SOCA v3-Micro 当前状态:                                               │
│  ├── 感知区 4 层(L1-L4)                                               │
│  ├── 工作空间 6 层(L5-L10)                                            │
│  │   ├── 前段 2 层(L5-L6):d_model=768                                │
│  │   ├── 中段 2×2 层(L7-L8 循环):d_bus=192                          │
│  │   └── 后段 2 层(L9-L10):d_model=768                              │
│  └── 动作区 4 层(L11-L14)                                             │
│                                                                         │
│  ✅ 通过:                                                              │
│  ├── 三区边界由 Down/Up Interface 显式标记                            │
│  ├── 工作空间有 Latent 瓶颈(768→192→768)                            │
│  └── 区域间注意力类型切换提供额外边界信号                             │
│                                                                         │
│  ⚠️ 问题 1:前段和后段仍在 d_model=768 空间                          │
│  ├── 只有中段在 d_bus=192                                             │
│  ├── 工作空间的"瓶颈"只覆盖 2/6 = 33% 的工作空间层                  │
│  ├── J-Space 要求整个工作空间都是低维的                              │
│  └── 修正:前段也应压缩到 d_bus 空间                                  │
│                                                                         │
│  ⚠️ 问题 2:循环中段的 J-Space 边界模糊                              │
│  ├── 2 层循环 2 次 = 逻辑上 4 层,但物理上只有 2 层                  │
│  ├── J-Space 的"层索引"是物理的还是逻辑的?                          │
│  ├── 如果循环 2 次,第 2 次的"层 7"和第 1 次的"层 7"是同一个还是不同? │
│  └── 修正:为循环引入显式"迭代索引"作为监控维度                      │
│                                                                         │
│  ❌ 问题 3:工作空间占比过低                                          │
│  ├── 原始设计建议:感知 20% / 工作空间 40% / 动作 40%               │
│  ├── 当前:4/14=29% / 6/14=43% / 4/14=29%                            │
│  ├── 工作空间占比合格(43%),但动作区偏少                             │
│  └── 可接受:验证模型不追求最优比例                                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.2 J-Lens 审查：Jacobian 路径是否清晰

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  J-Lens 要求:                                                           │
│  ├── 中间层到输出的映射近似线性                                        │
│  ├── 因果方向稀疏且稳定                                                │
│  ├── Jacobian 的 Top-K 方向解释 >80% 输出方差                         │
│  └── 非线性节点尽量少                                                  │
│                                                                         │
│  SOCA v3-Micro 当前状态:                                               │
│                                                                         │
│  ✅ 通过:                                                              │
│  ├── 中段使用 Linear Attention(无 softmax)→ Jacobian 可解析         │
│  ├── 感知区/动作区使用 Dense(无离散路由)→ 路径连续                  │
│  ├── 动作区 LoRA-MoE 是 Dense 的 → 无离散选择                        │
│  └── 残差连接保证梯度路径存在                                         │
│                                                                         │
│  ⚠️ 问题 4:Soft MoE 前段的 Jacobian 非线性                          │
│  ├── Token-Merge Soft MoE 的 dispatch 矩阵是 softmax 输出            │
│  ├── 虽然可微,但 softmax 引入强非线性                                │
│  ├── J-Lens 假设"近似线性"在此处不成立                              │
│  └── 修正方案:                                                        │
│      A. 将 dispatch 从 softmax 改为 sigmoid(独立门控)               │
│      B. 或:前段不用 Soft MoE,改用 Dense + 稀疏门控                 │
│      C. 推荐 A:sigmoid dispatch 保持可微且更线性                     │
│                                                                         │
│  ⚠️ 问题 5:循环中段的 Jacobian 链                                    │
│  ├── 2 层 × 2 次循环 = 4 层 Jacobian 链                              │
│  ├── 但权重共享 → Jacobian 是同一矩阵的幂                           │
│  ├── J = (J_L8 · J_L7)²                                              │
│  ├── 幂次结构实际上使 Jacobian 更稳定(特征值收敛)                  │
│  └── ✅ 这反而是优势:循环使 Jacobian 方向更集中                     │
│                                                                         │
│  ⚠️ 问题 6:后段 Sparse MoE 的 Jacobian 不连续                      │
│  ├── Top-K 路由是离散的 → Jacobian 在路由边界不连续                  │
│  ├── 但这是所有 Sparse MoE 的固有问题                                │
│  ├── 缓解:后段只有 2 层,影响有限                                    │
│  └── 修正:后段路由加温度退火(训练时软→推理时硬)                    │
│                                                                         │
│  ❌ 问题 7:注意力门控(Gated Attention)的 Jacobian 影响             │
│  ├── Gated DeltaNet 的门控值 β, α 是数据依赖的                      │
│  ├── 这使得 Jacobian 随输入变化(非固定线性映射)                    │
│  ├── 但门控值本身是可监控的 → 可以条件化 J-Lens                      │
│  └── 修正:J-Lens 分析时,固定门控值为批次均值                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.3 SAE 审查:稀疏可分解性

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  SAE 要求:                                                              │
│  ├── 激活空间天然稀疏                                                  │
│  ├── 特征近正交                                                        │
│  ├── 单义性(一个特征≈一个概念)                                      │
│  └── 无超级位置(superposition)                                         │
│                                                                         │
│  SOCA v3-Micro 当前状态:                                               │
│                                                                         │
│  ✅ 通过:                                                              │
│  ├── Joint SAE 联合训练(dict=256, K=8)                                │
│  ├── 工作空间有正交约束                                                │
│  ├── 中段 Multi-Head 天然将特征分到不同子空间                         │
│  └── 概念正交性损失已包含                                              │
│                                                                         │
│  ⚠️ 问题 8:SAE 字典太小(256)                                        │
│  ├── 192 维空间用 256 个字典向量 → 过完备比仅 1.33×                  │
│  ├── 业界标准:过完备比 ≥ 4×(即 192 维至少 768 个字典向量)           │
│  ├── 256 个字典无法充分分解 192 维空间                               │
│  └── 修正:dict_size 256 → 1024(过完备比 5.3×)                      │
│                                                                         │
│  ⚠️ 问题 9:SAE 只在中段施加                                          │
│  ├── 原始设计要求工作空间内多个采样点                                  │
│  ├── 当前只在中段(d_bus=192)有 SAE                                  │
│  ├── 前段和后段(d_model=768)无 SAE                                   │
│  └── 修正:在前段和后段各加一个轻量 SAE(dict=512, K=16)             │
│                                                                         │
│  ⚠️ 问题 10:激活稀疏化不够显式                                      │
│  ├── 中段有 Top-K 路由(稀疏)                                        │
│  ├── 但感知区和动作区是 Dense 的 → 激活不稀疏                        │
│  ├── Circuit Sparsity 的做法:99.9% 权重为零                          │
│  ├── SOCA 不需要这么极端,但应有温和稀疏                              │
│  └── 修正:感知区/动作区加 L1 稀疏惩罚(λ=0.001)                     │
│                                                                         │
│  ❌ 问题 11:缺少"特征单义性"的显式度量                              │
│  ├── 训练时没有监控"每个 SAE 字典向量是否只对应一个概念"             │
│  ├── 需要在验证阶段加入单义性评估                                    │
│  └── 修正:加入 Feature Purity 指标作为监控信号                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

│  └── 这直接验证 Circuit Sparsity 的思路是否可与 SOCA 结合             │

## 七、修正后的训练损失函数

```python
def compute_total_loss_v3_micro_rev(model, batch, config, step):
    """
    SOCA v3-Micro-REV 完整损失函数。
    包含所有修正。
    """
    # ═══ 主任务损失 ═══
    logits = model(batch['input_ids'])
    lm_loss = F.cross_entropy(logits.view(-1, 32000), batch['labels'].view(-1))
    
    # ═══ 稀疏性损失 [修正 P6] ═══
    sparse_loss = 0.0
    # 感知区 + 动作区:L1 软稀疏
    for layer in model.perception_layers + model.action_layers:
        sparse_loss += layer.ffn_activations.abs().mean()
    sparse_loss *= config.lambda_sparse  # 0.001
    
    # ═══ 正交性损失 ═══
    orth_loss = 0.0
    for layer in model.mid_layers:
        orth_loss += orthogonal_loss(layer.mh_moe.expert_weights)
    orth_loss *= config.lambda_orth  # 0.01
    
    # ═══ SAE 重建损失 [修正 P1, P5] ═══
    sae_loss = 0.0
    # 中段:主 SAE (dict=1024, K=8)
    for layer in model.mid_layers:
        recon, codes = layer.sae(layer.probe_output)
        sae_loss += F.mse_loss(recon, layer.probe_output)
    # 前段 + 后段:轻量 SAE (dict=512, K=16) [新增]
    for layer in model.front_layers + model.back_layers:
        recon, codes = layer.light_sae(layer.probe_output)
        sae_loss += 0.5 * F.mse_loss(recon, layer.probe_output)  # 权重减半
    sae_loss *= config.lambda_sae  # 0.15
    
    # ═══ 概念正交性损失 ═══
    concept_loss = config.lambda_concept * concept_orthogonality_loss(
        model.mid_activations, batch_size=32
    )
    
    # ═══ 路由辅助损失 ═══
    route_loss = 0.0
    for layer in model.mid_layers + model.back_layers:
        route_loss += layer.load_balancing_loss()
    route_loss *= config.lambda_route  # 0.01
    
    # ═══ 循环一致性损失 [修正 P7] ═══
    cycle_loss = 0.0
    if model.mid_section.n_iterations > 1:
        # 鼓励两次迭代的路由决策一致(收敛信号)
        r1 = model.mid_section.iter_routing[0]
        r2 = model.mid_section.iter_routing[1]
        cycle_loss = routing_consistency_loss(r1, r2) * 0.005
    
    # ═══ 总损失 ═══
    total = (lm_loss + sparse_loss + orth_loss + sae_loss + 
             concept_loss + route_loss + cycle_loss)
    
    return total
```

## 九、最终审查结论

### 9.1 通过项

| 维度 | 状态 | 说明 |
|---|:---:|---|
| 三区域结构 | ✅ | 4+6+4,边界由 Interface 显式标记 |
| 三维 MoE 覆盖 | ✅ | 5 种组合,三维全覆盖 |
| 混合注意力 | ✅ | DeltaNet + Gated Std + Linear,与 Qwen3.5/Kimi K3 一致 |
| Multi-Head 路由 | ✅ | 4h×8e,与 MAGI-2 同构(缩小版) |
| Latent MoE | ✅ | d_bus=256,与 Kimi K3 同思路 |
| 联合 SAE | ✅ | 三段 SAE(中段主 + 前后段轻量) |
| 广播总线 | ✅ | 每层写入,γ=0.99 |
| 循环机制 | ✅ | 2×2=等效 4 层,有门控+位置编码 |
| LoRA 持续学习 | ✅ | 动作区 2h×8 LoRA |
| 参数量 | ✅ | ~106M,适合快速验证 |

### 9.2 修正项

| 编号 | 修正 | 影响 |
|:---:|:---|:---|
| P1 | SAE dict: 256→1024 | 特征分解质量↑ |
| P2 | 前段 dispatch: softmax→sigmoid | J-Lens 友好 |
| P3 | 中段专家: 48→128→48 | 专家表达力↑ |
| P4 | 后段专家: 8→16, Top-4 | 组合多样性↑32× |
| P5 | 前段后段加轻量 SAE | 全工作空间可解释 |
| P6 | 感知/动作区加 L1 | 温和激活稀疏 |
| P7 | 循环加迭代位置编码 | 监控精度↑ |
| P12 | d_bus: 192→256 | d_head=64,更合理 |

### 9.3 保留待扩展项(0.8B-1.2B 时引入)

| 项目 | 原因 |
|---|---|
| MLA(Multi-head Latent Attention) | 14 层太浅,MLA 收益不明显 |
| Engram 条件记忆 | Bus 已覆盖基本需求 |
| 权重稀疏(非消融) | 需要更大模型验证性能-稀疏权衡 |
| DSA 稀疏注意力 | 短序列(2048)不需要 |
| Head Parallel 通信 | 单卡不需要 |

### 9.4 一句话总结

> **SOCA v3-Micro-REV 在 14 层 / ~106M 参数内,通过原生可解释性(J-Space 三区 + J-Lens 线性路径 + SAE 三段联合)、SOTA 架构匹配(Gated DeltaNet 混合注意力 + Multi-Head Latent MoE + Soft/Sparse/Dense 三激活)和三维 MoE 完整性(5 种组合全覆盖)的审查。发现并修正了 12 个问题(SAE 字典过小、Soft MoE 的 softmax 破坏 Jacobian 线性、专家维度过窄、路由组合空间不足等),新增 4 个消融实验(含 Circuit Sparsity 兼容性验证)。修正后的架构可直接进入训练,作为 0.8B-1.2B 正式设计的最小完整验证平台。**
