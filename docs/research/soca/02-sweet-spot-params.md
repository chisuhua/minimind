# SOCA v3-Micro 甜点参数量评估:从 106M 到最优验证区间

> **目的**:在 14 层 SOCA v3-Micro 架构下,寻找**验证充分性 × 训练成本**最优的参数量甜点。
>
> **核心问题**:106M 是否足够?是否需要 130M / 148M / 170M?
>
> **关联文档**:
> - 上游(14 层审查):[`01-v3-micro-14l-review.md`](./01-v3-micro-14l-review.md)
> - 下游(层数甜点):[`03-sweet-spot-layers.md`](./03-sweet-spot-layers.md)
>
> ---
>
> ## ⚠️ 版本状态：14L 历史配置（已被 03 升级为 16L × 155M）
>
> **本文档的 148M 甜点版是 14 层 SOCA v3-Micro 的参数量最优解**——但层数甜点研究(03)表明 16 层(5P+6W+5A) × 155M 是更优的联合甜点。
>
> 本文档的核心结论(130-170M 是参数量甜点区间 / 148M 是单层数最优点 / 5-8× 缩放外推区间可靠)对 **16L × 155M 配置仍然成立**,但具体数字需对齐到 03 §五.6：
>
> | 维度 | 本文档(14L) | 03 §五.6(16L 锁定) | 变化 |
> |---|---|---|---|
> | 物理层数 | 14 | **16** | +2 |
> | 中段专家 | 4h × 12e = 48, Top-4/head | **4h × 12e = 48, Top-4/head** | 不变 |
> | 后段专家 | 24 routed, Top-6 | **20 routed, Top-5** | 精简 |
> | 参数量 | ~148M | **~155M** | +7M |
> | 训练数据 | 6B token | 6B token | 不变 |
>
> **实施时请以 [`03-sweet-spot-layers.md`](./03-sweet-spot-layers.md) §五.6 的最终配置为准**;本文档的参数扫描方法论、统计功效分析、外推可靠性评估仍然有效。

## 一、106M → 150M 能解决什么?

### 1.1 逐项问题修复能力对比

| 审查问题 | 106M 下的状态 | 150M 下的改善 | 改善机制 |
|:---|:---|:---|:---|
| P1: SAE 字典小 | dict=1024, 过完备比 4× | dict=2048, 过完备比 8× | 多出的参数直接给字典 |
| P2: Soft MoE 非线性 | 已修正(sigmoid) | 不变 | 与参数量无关 |
| P3: 专家维度窄 | 64→128→64 (16.4K/专家) | 64→192→64 (24.6K/专家) | 专家中间层加宽 50% |
| P4: 后段组合少 | 16 专家, C₁₆⁴=1820 | **24 routed, Top-6, C₂₄⁶=134,596** | 专家数翻倍 |
| P5: 前后段无 SAE | dict=512 轻量 | dict=1024 标准 | 字典翻倍 |
| P6: 无激活稀疏 | L1 λ=0.001 | 不变 | 与参数量无关 |
| P7: 循环监控 | 迭代位置编码 | 不变 | 与参数量无关 |
| P12: d_head=64 | 256/4=64 | 256/4=64 | 不变 |

### 1.2 关键判断

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  106M → 150M 的核心收益                                                │
│                                                                         │
│  ✅ 能解决的:                                                           │
│  ├── 专家容量:每专家从 16.4K → 24.6K(+50%)                           │
│  │   → 专家能学到更复杂的特化模式                                     │
│  │   → 消融实验中"有专家 vs 无专家"的差异更显著                     │
│  │                                                                     │
│  ├── 后段组合空间:1820 → 35960(+20×)                                 │
│  │   → 路由多样性足够产生可测量的效果                                 │
│  │   → "不同路由策略"的消融对比更可靠                                │
│  │                                                                     │
│  ├── SAE 质量:过完备比 4× → 8×                                       │
│  │   → 特征分解更精细                                                 │
│  │   → "有 SAE vs 无 SAE"的监控差异更明显                           │
│  │                                                                     │
│  └── 统计功效:每组件参数更多 → 消融差异的效应量更大                 │
│      → 5B token 训练即可产生显著差异                                  │
│                                                                         │
│  ❌ 不能解决的:                                                        │
│  ├── 层数不足(14 层固定)→ 需要更多层才能验证深度效应               │
│  ├── 序列长度限制(2048)→ 需要更长上下文验证注意力                  │
│  ├── 数据量限制(5B token)→ 某些能力需要更多数据                    │
│  └── 多卡通信(单卡训练)→ 无法验证分布式相关设计                   │
│                                                                         │
│  结论:150M 对"验证架构组件是否有效"有实质帮助,                      │
│  但对"验证架构在大规模下是否仍然有效"帮助有限。                      │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 二、甜点参数量分析:多约束优化

### 2.1 约束条件

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  验证模型的五个约束                                                     │
│                                                                         │
│  C1. 训练时间约束                                                      │
│  ├── 目标:单次训练 ≤ 24 小时(8×A100-80G)                            │
│  ├── 消融实验:24 个消融 × 单次训练                                  │
│  ├── 总验证周期:≤ 7 天(含并行)                                    │
│  └── 推算:模型 ≤ 200M,5B token,batch=256×2048                     │
│                                                                         │
│  C2. 效应量约束                                                        │
│  ├── 消融差异必须 > 2× 标准差(统计显著)                            │
│  ├── 每组件至少需要 ~5M 参数才能产生可测量效应                       │
│  ├── 14 层 × 5 个区域 = 至少 70M 参数给"结构"                      │
│  └── 加上 Embedding(~25M)→ 最低 ~95M                               │
│                                                                         │
│  C3. 组件最小容量约束                                                  │
│  ├── 中段 MH-MoE:≥ 4 heads × 8 experts × 16K/expert = 0.5M        │
│  ├── 后段 Sparse:≥ 16 experts × 0.6M/expert = 9.6M                 │
│  ├── 前段 Soft:≥ 4 slots × 4 experts × 1.5M/expert = 24M          │
│  ├── 动作区 LoRA:≥ 2 heads × 8 LoRA × 8K/LoRA = 0.13M            │
│  ├── 注意力(14层):≥ 14 × 2.4M = 33.6M                             │
│  └── FFN(14层):≥ 14 × 3M = 42M                                    │
│                                                                         │
│  C4. 验证信噪比约束                                                    │
│  ├── 模型太小 → 随机噪声淹没架构效应                                │
│  ├── 经验法则:每消融组需要 ≥ 3 个"自由度"                          │
│  │   (即被消融的组件至少占模型 5% 参数)                            │
│  ├── 中段占模型 ≥ 5% → 模型 ≤ 中段参数/0.05                       │
│  └── 中段 ~2M → 模型 ≤ 40M?不对,这是下限约束                     │
│      实际:中段需要足够参数才能"有东西可消融"                       │
│                                                                         │
│  C5. 扩展可预测性约束                                                  │
│  ├── 验证模型的结论必须能外推到 0.8B-1.2B                           │
│  ├── 太小(<80M):某些效应是"小模型特有"的,不可外推                │
│  ├── 太大(>250M):训练成本增加但验证信息量不增加                  │
│  └── 最佳外推区间:100M-200M(文献共识)                             │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 三、甜点区间确定:130M ~ 170M

### 3.1 为什么是 130M-170M

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│  甜点区间:130M ~ 170M                                                  │
│                                                                         │
│  理由 1:统计功效                                                      │
│  ├── 130M 时,中段(核心验证目标)占 ~3-4M = 2.5-3%                   │
│  ├── 这刚好是"可消融且有可测量效应"的下限                           │
│  ├── 170M 时,后段占 ~20M = 12%,消融效应非常显著                    │
│  └── 超过 170M:后段效应不再增加(已饱和)                            │
│                                                                         │
│  理由 2:专家特化可观测性                                              │
│  ├── < 120M:每专家 < 15K 参数 → 特化不明显                         │
│  ├── 130-170M:每专家 20-30K → 特化可测量                           │
│  └── > 200M:每专家 > 40K → 但验证不需要这么精细                    │
│                                                                         │
│  理由 3:循环机制验证                                                  │
│  ├── 循环 2 次需要"第 1 次不够、第 2 次有增益"                      │
│  ├── < 100M:模型太小,1 次循环就够了(无法验证循环价值)             │
│  ├── 130-170M:复杂度刚好让 2 次循环有可测量增益                    │
│  └── > 200M:增益更大但训练成本不成比例增加                          │
│                                                                         │
│  理由 4:SAE 质量                                                      │
│  ├── dict=2048, d_bus=256 → 过完备比 8×                              │
│  ├── 需要模型产生足够丰富的激活分布                                   │
│  ├── < 120M:激活分布太简单,SAE 过度拟合                            │
│  ├── 130-170M:激活分布足够复杂,SAE 有真正的分解工作可做           │
│  └── 这与 OpenAI 在 0.4B Circuit Sparsity 中的观察一致               │
│                                                                         │
│  理由 5:训练成本                                                      │
│  ├── 150M, 5B token, 8×A100: ~16-18 小时                            │
│  ├── 24 个消融(可 4 并行): ~6 天                                   │
│  ├── 总计 1 周内完成全部验证                                         │
│  └── 对比 106M:只省 ~4 小时/次,但消融显著性下降                   │
│                                                                         │
│  理由 6:与 0.8B 的缩放比                                              │
│  ├── 150M → 800M = 5.3× 缩放                                        │
│  ├── 150M → 1200M = 8× 缩比                                         │
│  ├── 文献经验:5-10× 缩放比内,架构结论可靠外推                    │
│  └── < 100M → 800M = 8×+ 缩放,外推风险增大                        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 为什么不是 106M

```
106M 的具体不足:

1. 中段容量不足
   ├── 32 专家 × 16.4K/专家 = 0.52M 总专家参数
   ├── 每专家只能学一个非常简单的变换
   ├── 消融"有 MH vs 无 MH"时,差异 < 1%(不显著)
   └── 需要每专家 ≥ 25K 才能产生 > 2% 的消融差异

2. 后段组合空间不足
   ├── 16 专家, Top-4: C₁₆⁴ = 1820
   ├── 但 5B token 训练中,很多组合从未被使用
   ├── 路由学习不充分 → 消融"有路由 vs 无路由"差异小
   └── 需要充分覆盖组合空间——通过**增加专家数(≥32)** 或**提高 Top-K(≥6)** 都能满足;14L 148M 选 24 routed + Top-6(C₂₄⁶=134,596 > C₃₂⁴=35,960,组合覆盖更广)

3. 循环验证不充分
   ├── 2 层 × 16.4K/专家 → 每次迭代只做很少计算
   ├── 第 2 次循环的增益被噪声淹没
   └── 需要更多参数让"第 2 次循环"有实质性贡献

4. SAE 分解质量
   ├── 106M 模型的激活分布较简单
   ├── dict=1024 可能过度参数化(字典向量利用率 < 30%)
   └── 150M 模型的激活更丰富,字典利用率可达 50-70%
```

### 3.3 为什么不是 200M+

```
200M+ 的问题:

1. 训练成本不成比例增加
   ├── 200M vs 150M: 训练时间 +33%
   ├── 24 个消融 × 33% = 额外 ~2 天
   └── 但消融显著性只增加 ~5%(已接近饱和)

2. 开始引入"规模效应"混淆
   ├── > 200M 时,模型性能提升部分来自"更大"而非"架构更好"
   ├── 消融实验中,难以区分"架构贡献"和"容量贡献"
   └── 150M 以下,容量效应较小,架构效应更纯净

3. 不如直接跳到 0.8B
   ├── 如果预算允许 200M+ 验证
   ├── 不如直接训练 0.8B 的 10% 步数(等效验证)
   └── 或者用 200M 做 2 个消融,不如 150M 做 24 个消融

4. 单卡限制
   ├── 200M+ 在 8×A100 上需要模型并行
   ├── 增加工程复杂度
   └── 150M 可以舒适地放在单卡(80G)上
```

## 六、甜点区间的边界条件

### 6.1 下界:120M(低于此不可靠)

```
低于 120M 的具体风险:

1. 中段容量不足
   ├── < 120M 时,中段总参数 < 2.5M
   ├── 4 heads × 8 experts × 16K = 0.5M 专家参数
   ├── 每专家只能学"一个线性变换"级别的特化
   └── 消融"有 MH vs 无 MH"差异 < 1%,统计不显著

2. 循环机制无法验证
   ├── 2 层 × 小专家 = 每次迭代计算量太少
   ├── 第 2 次循环的增益 < 噪声水平
   └── 无法区分"循环有效"和"随机波动"

3. SAE 过拟合
   ├── 模型产生的激活分布太简单
   ├── dict=2048 对简单分布过度参数化
   └── SAE 重建误差极低但无实际分解意义

4. 外推不可靠
   ├── 120M → 800M = 6.7× 缩放
   ├── 在 < 120M 时,某些"架构效应"是小模型特有的
   └── 例如:小模型中注意力头更容易特化(因为头少)
```

### 6.2 上界:180M(高于此收益递减)

```
高于 180M 的问题:

1. 训练成本不成比例
   ├── 180M vs 150M: 训练时间 +20%
   ├── 24 消融 × 20% = 额外 ~1.5 天
   ├── 但消融显著性只增加 ~3%
   └── 性价比下降

2. 开始引入规模混淆
   ├── > 180M 时,模型开始展现"涌现能力"
   ├── 这些能力可能来自规模而非架构
   ├── 消融实验中难以区分"架构贡献"和"规模贡献"
   └── 例如:> 180M 时模型可能自发形成"类工作空间"结构
       即使没有显式分区

3. 工程复杂度增加
   ├── > 180M 在单卡 80G 上需要激活检查点
   ├── 增加训练工程复杂度
   └── 与"快速验证"的目标矛盾

4. 不如直接做 0.8B
   ├── 如果预算允许 200M+ 验证
   ├── 不如用同样预算训练 0.8B 的 20% 步数
   └── 直接在目标规模上验证更有说服力
```
