## 0. 文档范围与定位

本文档定义 **agenticmemory 记忆模型** 的评估框架——如何**证明** KV 缓存确实包含了推理所需的全部信息,以及如何**证明** Wiki DAG 作为完整性证明的有效性。

**与现有评估体系的关系**:
- 本评估**聚焦记忆模型本身的评估**(KV 缓存是否包含推理信息)
- HydraForgeBench([`../agenticdsl-training/04-evaluation-benchmark.md`](../agenticdsl-training/04-evaluation-benchmark.md))聚焦** AgenticDSL 生成器评估**
- 两者评估目标不同,但都遵循 AGENTS.md §7 的 8 维度框架

**多轮对话场景的评估**:本文档聚焦单文档场景。对话特化评估维度(指代消解准确率、信息更新追踪率、约束累积完整率、意图追踪准确率、长对话保持率、增量更新正确率)见 [`04-dialogue-extension.md`](04-dialogue-extension.md) §10。

**评估方法论**:本文档定义"评估什么指标"。**用什么方法评估**(Probe Model 验证、Golden Filter、效用增益对比)详见 [`06-evaluation-methodology.md`](06-evaluation-methodology.md)。

## 1. 终极验证标准

> **基于记忆模型生成的 Wiki 回答推理问题的准确率 / 基于原文回答的准确率 ≥ 0.98**

```
B/A ≥ 0.98

其中:
  B = 基于 Wiki 回答推理问题的准确率(记忆模型通道)
  A = 基于原文回答推理问题的准确率(原文基线)
```

这是评估的**唯一终极标准**——其他指标都是这一标准的辅助验证手段。

## 2. 双轨评估流程

### 2.1 完整流程

```
Phase 1: 准备测试集
  → N 篇测试文档(覆盖各类型:事实密集/推理密集/对话/混合)
  → 每篇文档配套 M 个评估问题(覆盖 8 种推理类型)
  → 每道题有标准答案(基于原文人工标注或教师模型标注)

Phase 2: 记忆模型对测试文档生成 Wiki 页面
  → input: 测试文档
  → output: Wiki 页面(含 irr_estimate)

Phase 3: 为每篇文档生成评估问题
  → 教师模型基于原文档生成 M 个推理型问题 + 标准答案
  → 问题类型分布:数值/因果/对比/条件/时序/综合/排除/反事实

Phase 4: 双轨评估
  轨道 A: LLM 基于原始文本回答 → 答案集 A
  轨道 B: LLM 基于 Wiki 文本回答 → 答案集 B
  (两个轨道用同一个 LLM,仅输入文本不同)

Phase 5: 对比 A 和 B 的事实准确性
  → 按问题类型分别计算 B/A
  → 整体 B/A 加权平均

Phase 6: 按问题类型分析降级情况
  → 哪些推理类型降级最严重?
  → 哪些文档类型降级最严重?

Phase 7: 根因定位
  → 找到轨道 B 错误但 A 正确的问题
  → 分析该问题需要什么信息
  → 检查原文 vs Wiki,定位信息丢失位置
  → 分类统计:数值丢失/条件丢失/因果丢失/实体混淆
```

### 2.2 关键设计原则

| 原则 | 说明 |
|---|---|
| **同一 LLM** | 轨道 A 和 B 必须用同一个推理 LLM,排除 LLM 差异 |
| **同一问题** | 同一道题在两个轨道独立回答,排除问题理解差异 |
| **盲评** | 评估时不知道是 A 还是 B,避免主观偏向 |
| **抽样人工** | 关键评估问题有人工抽检(≥ 10%) |

## 3. 六维度评估指标

### 3.1 指标全景

| 维度 | 核心指标 | 目标值 | 评估对象 |
|---|---|---|---|
| **提取准确性** | CaRB F1 / 图编辑距离 / BERTScore | F1 ≥ 55% | Wiki 页面与原文的一致性 |
| **格式合规性** | JSON 合法率 / Schema Valid@1 | Valid@1 ≥ 90% | Wiki 输出格式 |
| **事实准确性** | 反向验证 entailment 率 / 幻觉率 | entailment ≥ 85% | Wiki 内事实正确性 |
| **能力边界** | 分层准确率 / 自知之明准确率 | 分层 ≥ 75%,自知 ≥ 80% | 模型边界识别能力 |
| **信息完整性** | IRR / 双轨问答准确率差 | IRR ≥ 0.90,B/A ≥ 0.98 | KV 缓存完整性 |
| **鲁棒性** | 扰动一致性 / 位置偏差 | 一致性 ≥ 90%,偏差 < 5% | 抗扰动能力 |

### 3.2 IRR(Information Recall Rate,信息召回率)

```
IRR = (Wiki 页面中正确召回的原文信息数) / (原文中应被提取的信息总数)

计算方法:
  1. 教师模型标注原文中所有"应被提取的信息"(RSI 列表)
  2. 检查 Wiki 页面是否覆盖了 RSI 中的每一条
  3. IRR = 1 - |missing_RSI| / |total_RSI|

示例:
  原文中 RSI 共 47 条
  Wiki 中覆盖 44 条,丢失 2 条,幻觉 1 条
  IRR = 44 / 47 = 0.936
```

### 3.3 能力边界维度详解

#### 3.3.1 分层准确率

```
对每条原文信息,模型必须正确判断:
  - 这是记忆层(直接提取)
  - 这是领域辅助层(需领域知识)
  - 这是混合层(边界)
  - 这是推理层(交给推理模型)

准确率 = (正确分层的样本数) / (总样本数)
目标 ≥ 75%
```

#### 3.3.2 自知之明准确率

```
对需要推理模型验证的推理链,模型应正确标注:
  needs_reasoning_model_verification = true

对纯记忆层的信息,模型应:
  needs_reasoning_model_verification = false

自知之明准确率 = (正确标注的样本数) / (总样本数)
目标 ≥ 80%
```

### 3.4 信息完整性维度详解

#### 3.4.1 双轨问答准确率差

```
B/A 比值计算:
  B = 基于 Wiki 的问答准确率
  A = 基于原文的问答准确率
  
  B/A ≥ 0.98(终极标准)
  
  按推理类型分层:
    数值推导 B/A ≥ 0.99(数值必须最精确)
    因果推理 B/A ≥ 0.95
    对比推理 B/A ≥ 0.98
    条件推理 B/A ≥ 0.95
    综合判断 B/A ≥ 0.90(允许略有下降)

  按推理深度分层:
    单步推理 B/A ≥ 0.99
    双步推理 B/A ≥ 0.95
    三步推理 B/A ≥ 0.90
```

#### 3.4.2 位置偏差

```
文本开头信息的推理准确率 vs 中间 vs 结尾
三个位置的差异 < 5%
(消除"中间信息被遗忘"的位置偏差)
```

## 4. KV 缓存验证实验

### 4.1 实验 1:KV 消融测试

```
实验目的:验证 KV 缓存确实是推理信息的载体

正常轨道:
  处理文本 → KV 缓存 → 推理问题 → 答案 ✓

消融轨道:
  处理文本 → 清空 KV 缓存 → 推理问题 → 答案 ✗(随机/失败)

预期:消融后准确率下降 > 50%
  → 证明 KV 缓存确实是推理的关键
  → 如果消融后准确率几乎不变 → 说明 KV 没承载关键信息(失败)
```

### 4.2 实验 2:KV 扰动测试

```
实验目的:验证 KV 缓存区分相似但不同的信息

文本 A(总参数 284B)→ KV_A → 推理"总参数是多少?" → 答案 284B
文本 B(总参数 285B)→ KV_B → 推理"总参数是多少?" → 答案 285B

预期:
  - 答案 A ≠ 答案 B
  - 答案 A 基于原文 A 的 284B
  - 答案 B 基于原文 B 的 285B
  → 证明 KV 缓存精确编码了具体数值
```

### 4.3 实验 3:推理链溯源

```
实验目的:验证推理链可追溯到 KV 缓存

步骤:
  1. 让模型输出推理链
  2. 对推理链的每一步中间步骤,要求模型给出"来自 KV 缓存的证据"
  3. 检查这些证据是否真实存在于 KV 缓存中

预期:
  - ≥ 90% 的中间步骤可溯源到 KV 缓存
  → 证明推理链不是幻觉,而是基于 KV 中的信息
```

### 4.4 实验 4:Wiki DAG 重建验证

```
实验目的:验证 Wiki DAG 作为"KV 完整性证明"的有效性

步骤:
  1. 从原文本构建 Wiki DAG(训练时已经构建)
  2. 用探针从训练后的模型 KV 缓存中提取所有实体和关系
  3. 对比提取结果与 Wiki DAG:
     - Wiki DAG 中有的实体,探针能否找到? → 实体召回
     - Wiki DAG 中有的关系,探针能否提取? → 关系召回

预期:
  - 实体召回 ≥ 95%
  - 关系召回 ≥ 90%
```

## 5. 能力边界探测

### 5.1 六级深度探测

```
Level 0(纯表面提取)
  → 测试:抽取文本中所有命名实体
  → 预期准确率 > 90%

Level 1(同义词归一化)
  → 测试:把"入职/加入/就职"统一视为同一关系
  → 预期准确率 > 85%

Level 2(代词消解)
  → 测试:把"该公司"解析为"DeepSeek"
  → 预期准确率 > 80%

Level 3(时间归一化)
  → 测试:把"去年 Q3"归一为"2025 年 Q3"
  → 预期准确率 > 75%

Level 4(领域知识辅助一步推导)
  → 测试:已知 LGD = 1 - 回收率,推出"回收率 = 65%"
  → 预期准确率 > 60%

Level 5(两步推导)
  → 测试:从多个事实组合推理
  → 预期准确率 < 50%(应显著下降)
```

### 5.2 边界自动检测

```
对每条原文信息,自动判定:

if 模型提取准确率 ≥ 0.85:
  → 该信息在模型能力范围内
elif 模型标注 needs_reasoning_model_verification=true 且置信度 < 0.7:
  → 该信息需要推理模型辅助
else:
  → 边界样本(进人工审核)
```

## 6. 失败诊断与迭代

### 6.1 失败诊断流程

```
当 B/A < 0.98 时:

Step 1: 找到轨道 B 错误但 A 正确的问题
  → 收集所有 B≠A 的问题

Step 2: 分析该问题需要什么信息
  → 用教师模型标注每个问题需要的 RSI

Step 3: 检查原文是否包含该 RSI
  - if 原文没有 → 问题本身不合理,排除
  - if 原文有 → 继续

Step 4: 检查 Wiki 页面是否包含该 RSI
  - if Wiki 没有 → KV 缓存丢失了该信息
  - if Wiki 有但 B 答错 → Wiki 表达有误

Step 5: 分类统计丢失的信息类型:
  - 数值丢失 → 强化数值编码训练
  - 条件丢失 → 强化条件限定训练
  - 因果丢失 → 强化因果关系训练
  - 实体混淆 → 强化实体区分训练
  - 时间丢失 → 强化时间归一化训练
  - 否定丢失 → 强化否定处理训练
```

### 6.2 针对性补充训练数据

```
诊断结果 → 针对性补充:

if 数值丢失率 > 10%:
  → 增加 Type A 数值样本占比至 50%
  → 在损失函数中数值权重从 5x 提升到 7x

if 条件丢失率 > 10%:
  → 增加 Type B(领域增强)样本
  → 增加条件查询训练样本

if 否定丢失率 > 10%:
  → 增加 Type E-3(否定事实处理)样本占比
  → 训练数据中否定类样本比例从 10% 提升到 20%

if 实体混淆率 > 10%:
  → 增加多实体绑定数据(50K-80K)
  → 实体边界 token 损失权重提升到 5x
```

### 6.3 迭代周期

```
诊断 → 补充训练数据 → 重训 → 重评估 → 再诊断
                     ↑
                     └─ 一个完整迭代周期约 1-2 周
```

## 7. 在线监控与持续验证

### 7.1 部署后持续监控指标

| 指标 | 监控频率 | 告警阈值 |
|---|---|---|
| Wiki 格式合法率 | 实时 | < 95% 告警 |
| Schema 遵从率 | 每小时 | < 85% 告警 |
| IRR 自报告均值 | 每小时 | < 0.85 告警 |
| needs_reasoning_model 标注率 | 每小时 | < 60% 或 > 95% 告警 |
| 推理准确率(抽样) | 每日 | B/A < 0.95 告警 |

### 7.2 Schema 漂移检测

```
每月自动检查:
  1. 采样 1000 条新输出
  2. 检查是否出现 schema 外的实体类型或关系类型
  3. 统计新增类型的频率
  
触发 schema 演化:
  - 连续 2 周出现 > 10% 的"schema 外"类型
  - 人工抽检发现 schema 缺失
  
更新流程:
  1. 收集新的四元组(schema 外的)
  2. 对新关系/实体做聚类 + LLM 概念化
  3. 与现有 schema 做合并检查
  4. 生成 schema v(n+1)
  5. 用新 schema 重新标注增量数据
  6. 增量训练小模型(仅 0.5 epoch)
```

### 7.3 灾难性遗忘防护

```
策略 1: Replay Buffer
  每次微调混入 30% 通用数据
  → 防止新训练遗忘旧能力

策略 2: EWC(Elastic Weight Consolidation)
  对通用能力参数施加正则化
  → 保护重要参数的更新幅度

策略 3: 定期回归测试
  在 CaRB / WiRe57 / BenchIE 上测试
  下降 > 5% 告警
```

## 9. 评估数据集设计

### 9.1 测试集组成

| 子集 | 规模 | 构成 | 用途 |
|---|---|---|---|
| **Set A(基础)** | 200 篇 | 短文(512-2048 tokens),事实密集 | 评估基础提取准确性 |
| **Set B(长文档)** | 100 篇 | 长文(4096-16384 tokens),推理密集 | 评估长上下文保持 |
| **Set C(对话)** | 100 篇 | 多轮对话,信息分散 | 评估跨轮次保持 |
| **Set D(对抗)** | 50 篇 | 易混淆数值/否定/未提及 | 评估鲁棒性 |
| **总计** | 450 篇 | 混合 | 综合 B/A 计算 |

### 9.2 问题生成协议

```
每篇文档配套生成 20-30 个问题:

1. 教师模型基于原文档生成 RSI(推理支撑信息列表)
2. 对每条 RSI 生成至少 3 种查询:
   - 正向查询(问 X 的值)
   - 反向查询(哪个实体的值是 Y)
   - 关系查询(X 和 Y 关系)
3. 覆盖 8 种推理类型
4. 包含至少 10% 的"原文未提及"问题(测试模型正确拒绝)
5. 标准答案必须:
   - 一致性:可从原文推出
   - 正交性:不泄露原文之外信息
   - 精度:数值保留原值
```
