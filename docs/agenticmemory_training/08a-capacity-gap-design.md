## 1. 总体架构与目标定义

### 1.1 最终产物

一个**专注于结构化记忆输出的小参数模型**（参数量区间 **500M–1.5B**，默认 **0.6B 作为"记忆引擎"**），其核心能力是：给定一段原始文本，输出符合自动涌现 schema 的结构化知识单元（实体-关系-实体四元组 + 概念标注 + 置信度分数）。

### 1.3 与 AgenticMind 顶层目标的解耦（重要）

> **本管线的训练目标（"记忆引擎"，≤1.5B）与 AGENTS.md §12.10 F-01 待决策项（AgenticDSL 生成器的 base 模型：<1B vs 7B）是两个独立决策**。

| 维度 | 本管线（记忆蒸馏）| AGENTS.md F-01（AgenticDSL 训练）|
|------|------------------|-------------------------------|
| **模型定位** | 6 层知识形态栈的 **L3 层** 记忆引擎 | **L4 层** AgenticDSL 语言生成器 |
| **能力要求** | 结构化记忆提取（不需推理）| 符号化 DSL 生成（含推理）|
| **候选 base** | 0.6B / 1.5B / 其他 | 待定（<1B vs 7B 需用户决策）|
| **训练算法** | SFT 三阶段 + 结构化蒸馏 | ReSTᴱᴹ → PRM → GRPO |
| **数据来源** | 本管线 OpenIE + Schema | AgenticDSL 运行时 trace |

> **结论**：本管线的 base 模型选型与 F-1 不构成耦合，本文档可独立决策。建议本管线锁定为 **0.6B 作为默认**，与项目顶层"<1B"目标保持一致；F-1 的最终决策不影响本管线产物。

## 2. Phase 0:语料准备与领域自适应基线校准

> **v1.2 实现指引**:Phase 0 实操见 [`08-memory-distillation-pipeline.md` §四](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

### 2.1 语料采集与清洗

| 步骤 | 操作 | 工具/方法 |
|------|------|-----------|
| 采集 | 按目标领域收集原始文本（研报、论文、新闻、文档等） | 爬虫 + API |
| 去重 | MinHash 近似去重（阈值 0.8） | datasketch 库 |
| 清洗 | 去除 HTML/特殊字符、修复编码、语言检测 | trafilatura + langdetect |
| 分块 | 按语义段落切分，保留上下文窗口（512-1024 tokens） | 基于段落边界 + 滑动窗口 |

### 2.2 领域自适应基线校准（关键步骤）

**问题**：探针模型的"能提取什么"高度依赖其预训练数据分布。如果某领域在预训练数据中占比低，即使是简单事实也可能被漏提，导致错误归入"推理层"。

**解决方案**：

```
Step 1: 从目标领域语料中采样 5000-10000 条文本块
Step 2: 在探针模型上进行 1-2 epoch 的 continued pretraining（仅 LM head 微调）
Step 3: 用校准后的探针模型建立"领域基线提取能力"
Step 4: 后续所有 Capacity Gap 判断均基于此校准后的基线
```

**成本估算**：5000 条 × 512 tokens ≈ 2.5M tokens，在单卡 A100 上约 15 分钟完成，在 RTX 4090 上约 20 分钟。

## 3. Phase 1:双盲 OpenIE 提取

> **v1.2 实现指引**:Phase 1 实操见 [`08-memory-distillation-pipeline.md` §五](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

### 3.1 模型选型

| 角色 | 推荐模型 | 参数量 | 理由 |
|------|----------|--------|------|
| 教师 | DeepSeek V4 Flash | 总 284B / 激活 13B | MoE 架构，推理能力接近旗舰，成本可控 |
| **主探针 (L1)** | **Qwen3-1.7B** | 1.7B 稠密 | 与教师激活比 ≈ **7.6×**，落在有效蒸馏区间 |
| **辅助探针 (L2，可选)** | **Qwen3-4B** | 4B 稠密 | Gap 3.25×，用于渐进 Gap 插值（见 §4.3）|
| **崩溃对照组 (L3)** | **Qwen3-0.6B** | 0.6B 稠密 | 排除 trivial 样本，与教师 21.7× Gap |

**为什么不用 500M 做主探针？** 500M 模型的 OpenIE 基础能力太弱（连基本的主谓宾提取都不稳定），其"提取失败"更多反映的是语言理解能力不足而非知识的推理复杂度。1.7B 是一个经过验证的"能做基本结构化提取、但做不了复杂推理"的阈值。

> **关键：Tokenizer 对齐硬约束（v0.1 缺失项，本修订新增）**
>
> 所有探针模型必须与教师模型**共享 tokenizer**，或至少**同系列内 tokenizer 完全对齐**。
>
> - DeepSeek V4 Flash 与 Qwen3 系列使用**不同的 tokenizer**，跨系列比较会被分词噪声污染概率分布
> - Qwen3-0.6B / 1.7B / 4B **共享同一 tokenizer**（vocab_size = 151,936），逐 token 概率对比零噪声
> - **违反此约束的探针选型会被拒绝**——结论不可靠

**探针架构选型矩阵：**

| 方案 | 探针组合 | 显存占用（4090 单卡）| 适用场景 |
|------|---------|---------------------|---------|
| 单探针（v0.1 原始）| L1: 1.7B | ~4.2 GB | 资源极度受限，仅做基础 Gap 信号 |
| **推荐双探针** | L1: 1.7B + L3: 0.6B | ~5.7 GB | **资源与精度平衡，覆盖 trivial 样本排除** |
| 三探针（可选增强）| L1: 1.7B + L2: 4B + L3: 0.6B | ~15.2 GB | 设计了 L2 渐进 Gap 消费逻辑后才推荐 |

> **注意**：当前 RTX 4090 实现版本（见 `08-memory-distillation-pipeline.md` §6.3）采用双探针（1.7B + 0.6B）。三层架构的 L2 (4B) 仅在实现**实际消费 4B 输出做 Gap 插值校准**时才推荐启用。

### 3.2 OpenIE 提取 Prompt 设计

对教师和探针模型使用**完全相同的 prompt**,确保公平比较。设计意图:
- 输出格式约束(JSON JSON 数组,字段固定)
- 5 类字段(subject / relation / object / confidence / evidence_span)
- 3 条要求(完整提取 / 动词短语关系 / 原文标准表述)

> **v1.2 边界声明**:完整 Prompt 模板(含 few-shot 示例与错误处理)见 [`08-memory-distillation-pipeline.md` §五.1 教师客户端](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档不重复 Prompt 原文,仅保留设计要点。
4. 如果一条信息需要多步推理才能得出，仍然提取，但在confidence中标注较低分值

文本：{input_text}
```

### 3.3 提取参数（v0.1 修订）

| 参数 | 教师 | 探针（L1/L3）| 理由 |
|------|------|---------------|------|
| `temperature` | **≤ 1.0**（默认 0.7）| **1.0**（不加热）| **v0.1 修订**：v0.1 原文"T=2.0 展开暗知识"论证**不成立**。T=2.0 在 JSON 单次采样中只增加解析失败率。正确做法：单次采样 T≤1.0 + top_logprobs=20，**logits 排序与温度无关**，top_logprobs 已完整保留分布信息 |
| `top_logprobs` | **20** | 100（vLLM 服务端需配 `--max-logprobs 100`）| 取分布前 N 个 token 用于置信度 |
| `thinking` / `reasoning_effort` | **`off`** / **`low`** | N/A | 关闭推理链，纯记忆提取 |
| `stop` | — | `["\n\n"]` | 防止生成新段落污染 JSON 数组 |

### 3.4 教师置信度提取方法（v0.1 修订）

> **v0.1 原文**:使用首 token logprob 作为教师整体置信度。
> **问题**:JSON 数组首 token 必为 `[`,top1_prob ≈ 1.0 恒成立,信号无信息量。
>
> **修订**:使用**答案 span 平均 logprob** 或 tuple 自带 `confidence` 字段。

> **v1.2 边界声明**:具体实现见 [`08-memory-distillation-pipeline.md` §五.1 教师客户端](../../agenticmemory_training/08-memory-distillation-pipeline.md)(DeepSeek V4 Flash API 调用 + logprob 解析)。本文档不重复实现代码,仅保留设计原理(答案 span 平均 logprob 取代首 token logprob)。

## 4. Phase 2:Capacity Gap 自动分层

> **v1.2 实现指引**:Phase 2 实操见 [`08-memory-distillation-pipeline.md` §六](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

### 4.1 核心分层逻辑

```python
def stratify(teacher_tuples, probe_tuples, l3_tuples, text_block):
    memory_candidates = []   # 候选记忆层
    reasoning_candidates = [] # 候选推理层
    uncertain = []           # 不确定区（CCS 0.3-0.7）
    
    for t_tuple in teacher_tuples:
        matched = semantic_match(t_tuple, probe_tuples, threshold=0.85)
        
        if matched:
            # 探针也能提取 → 候选记忆
            memory_candidates.append({
                "tuple": t_tuple,
                "stratification_signal": "capacity_gap_intersection",
                "probe_confidence": matched.confidence,
                "teacher_confidence": t_tuple.confidence
            })
        else:
            # 探针提取不出 → 候选推理
            reasoning_candidates.append({
                "tuple": t_tuple,
                "stratification_signal": "capacity_gap_difference",
                "gap_reason": analyze_gap_reason(t_tuple, text_block)
            })
    
    # 关键：用 L3 排除 trivial 样本（见 §4.3）
    memory_candidates = exclude_trivial(memory_candidates, l3_tuples)
    
    return memory_candidates, reasoning_candidates, uncertain
```

### 4.2 语义匹配策略

不能用精确字符串匹配，因为教师和探针可能对同一事实使用不同的表述。采用**三层匹配**：

| 层级 | 方法 | 匹配粒度 | 阈值 |
|------|------|----------|------|
| L1 | 实体归一化 + 精确匹配 | subject 和 object 归一化后完全一致 | 1.0 |
| L2 | 嵌入相似度 | 用 sentence-transformer 对 (s,r,o) 拼接后计算余弦相似度 | ≥ 0.85 |
| L3 | NLI 蕴含判断 | 用小 NLI 模型判断"探针提取是否蕴含教师提取" | entailment ≥ 0.7 |

三层依次执行，L1 命中则直接通过，L1 未命中走 L2，L2 未命中走 L3。

### 4.3 边界样本的二次验证

**类型 A：教师高置信但探针低置信的"疑似推理类"**

```
验证方法：重构敏感度扰动测试（v0.1 修订：明确扰动协议）
1. 对四元组做受控扰动：
   - 类型 1（同义改写）："出生于" → "诞生于"
   - 类型 2（实体替换）："DeepSeek" → "Anthropic"
   - 类型 3（关系翻转）："发布" → "被发布"  
   每种类型生成 3 个扰动样本
2. 将扰动后的文本重新输入教师模型
3. 计算教师输出的变化幅度：
   Δoutput = 1 - cosine_sim(embed(orig_output), embed(perturbed_output))
4. Δoutput > 阈值 → 确认推理类
5. Δoutput ≤ 阈值 → 降级为记忆类（可能是探针的注意力失败）
```

**类型 B：教师低置信的"疑似噪声"**

```
验证方法：结构化提取瓶颈测试
1. 让 L3 (0.6B) 模型独立尝试从原文提取该四元组
2. 能提取 → 确认记忆类（教师只是表述不确定）
3. 不能提取 → 升级为推理类或标记为低质量丢弃
```

**类型 C（v0.1 修订新增）：trivial 样本排除**

```
目的：排除"连 0.6B 都能提取的 trivial 事实"——这些样本没有训练价值

验证方法：
1. 让 L3 (0.6B) 对所有进入候选记忆层的四元组做提取
2. L3 能提取 → 该样本进入"trivial 集"，不进入训练
3. L3 不能提取 → 该样本保留为非平凡记忆

前置校准（Oracle B-6 修订）：
- L3 bottleneck 信号仅在 L3 自身的 zero-shot OpenIE F1 ≥ 0.4 时可信
- 低于阈值说明 L3 指令遵循能力不足，bottleneck 信号改用集成一致性（ensemble agreement）
```

### 4.4 连续谱系替代硬性二分

最终不采用 0/1 二分，而是为每条四元组计算 **Compute Complexity Score (CCS)**：

```python
CCS = w1 × capacity_gap_signal + w2 × reconstruction_sensitivity + w3 × extraction_bottleneck

# capacity_gap_signal: 0(交集) 或 1(差集)
# reconstruction_sensitivity: 扰动后输出变化，归一化到 [0,1]，见 §4.3 类型 A
# extraction_bottleneck: 0(L3能提取) 或 1(L3不能提取)

# 默认权重
w1, w2, w3 = 0.5, 0.3, 0.2

# 分层决策
if CCS < 0.3:    → 记忆层（高置信）
elif CCS > 0.7:  → 推理层（高置信）
else:            → 混合层（不进训练，进入人工审核队列）
```

> **关键（v0.1 修订）**：0.3~0.7 不是"待定"，是**硬约束——进人工审核队列**。这条规则必须严格执行，避免灰色地带被粗暴归类。

## 5. Phase 3:Schema 自动涌现

> **v1.2 实现指引**:Phase 3 实操见 [`08-memory-distillation-pipeline.md` §七](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

这是整个方案中最具创新性的部分。目标：**不人工预定义任何 schema，让 schema 从数据中自然涌现。**

### 5.1 技术路线选择

综合比较三种路线后，采用**"聚类优先 + LLM 概念化修正"的混合路线**：

| 路线 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| 纯聚类 | 完全数据驱动、无 LLM 成本 | 语义精度有限、难以处理同义关系 | 大规模粗筛 |
| 纯 LLM 概念化 | 语义精度高、可生成自然语言定义 | 成本高、存在幻觉风险 | 精细修正 |
| **混合（推荐）** | 兼顾效率和精度 | 流程稍复杂 | **本方案** |

这一选择得到了 AutoSchemaKG 框架（港科大 + 华为，2025）的实证支持：他们在 5000 万文档上实现了 92% 的 schema 语义对齐率，零人工干预。

### 5.2 四阶段 Schema 涌现流程

**阶段 5.2.1：关系类型聚类**

```
输入：所有记忆层四元组的 relation 字段（去重后约 5000-50000 个唯一关系表述）
方法：
  1. 用 sentence-transformer (all-MiniLM-L6-v2) 编码所有关系表述
  2. UMAP 降维到 128 维
  3. HDBSCAN 聚类（min_cluster_size=10, min_samples=5）
     - 选择 HDBSCAN 而非 K-Means：不需要预设簇数，能自动发现噪声点
  4. 每个簇内的关系表述归一化为一个"原始关系簇"
输出：[{cluster_id, canonical_form, member_relations[], size}]
```

**阶段 5.2.2：实体类型聚类**

```
输入：所有记忆层四元组的 subject/object 字段
方法：
  1. 先做 NER 标注（用 spaCy 或 GLiNER），识别实体类别
  2. 对同一实体在不同四元组中的表述做归一化（实体消歧）
  3. 用嵌入聚类将实体归入类型簇
  4. 每个类型簇标注一个"原始实体类型"
输出：[{cluster_id, canonical_form, member_entities[], type_hint}]
```

**阶段 5.2.3：LLM 概念化与层级化**

这是让 schema 从"原始簇"跃升为"语义概念"的关键步骤，借鉴 AutoSchemaKG 的 Extract-Define-Canonicalize 范式：

```
对每个关系簇和实体类型簇：

Prompt:
"""
以下是一组从文本中自动提取的关系表述，它们属于同一个语义簇：
{member_relations}

请完成以下任务：
1. 为这组关系定义一个规范的关系类型名称（简洁、通用）
2. 用一句话定义这个关系类型的语义含义
3. 判断它是否与以下已有关系类型重复：{existing_types}（如果有，给出应合并到的目标类型）
4. 标注这个关系的典型定义域（subject 的实体类型）和值域（object 的实体类型）

输出格式：
{
  "canonical_name": "...",
  "definition": "...",
  "merge_with": null 或 "已有类型名",
  "domain": ["实体类型1", "实体类型2"],
  "range": ["实体类型1", "实体类型2"]
}
"""
```

**LLM 概念化参数（v0.1 修订）：**

- **`temperature = 0.0`**：消除随机性，确保可复现
- **schema 概念化场景高温不适用**——这与教师提取的"暗知识展开"是不同场景，概念化是确定性的语义归并任务

**阶段 5.2.4：约束生成与 Schema 固化**

```
基于概念化结果，自动生成以下约束：

1. 类型约束（Type Constraints）：
   - 每种关系类型的 subject 和 object 必须是哪些实体类型的实例
   
2. 基数约束（Cardinality Constraints）：
   - 从数据统计中推断：每种关系的 (subject, object) 对是 1:1, 1:N, 还是 M:N
   - 例如："任职于" 是 N:1（一个人只能有一个当前雇主）

3. 互斥约束（Mutual Exclusion）：
   - 同一 subject 不能同时拥有互斥关系的 object
   - 例如："状态" 不能同时是 "活跃" 和 "已关闭"

4. 层级约束（Hierarchical Constraints）：
   - 实体类型和关系类型的上下位关系
   - 例如："公司" is-a "组织"，"收购" is-a "商业交易"
```

### 5.3 Schema 涌现的质量保障

| 风险 | 缓解措施 |
|------|----------|
| 聚类过度合并（不同语义的关系被归入同一簇） | 设置簇内最大语义距离阈值（余弦 ≥ 0.7），超过则强制拆分 |
| 聚类过度分裂（同一语义的关系被拆成多个簇） | LLM 概念化阶段做跨簇合并检查 |
| LLM 概念化幻觉（生成了不存在的关系类型） | 要求 LLM 每个输出必须引用至少 3 个原始关系表述作为证据 |
| Schema 膨胀（类型过多） | 设置 schema 规模上限（如 ≤ 200 种关系类型），通过关联规则挖掘合并低频类型 |

### 5.4 最终 Schema 产出物

Schema 完整数据结构(`schema_v1.json`)设计要点:
- 顶层字段:`schema_version` / `entity_types[]` / `relation_types[]` / `constraints[]`
- `entity_types`:每条含 `id` / `name` / `definition` / `parent`(层级)/ `examples[]`
- `relation_types`:每条含 `id` / `name` / `definition` / `domain[]` / `range[]` / `cardinality` / `surface_forms[]`
- `constraints`:支持 4 类(`type_constraint` / `cardinality` / `mutual_exclusion` / `hierarchical`)

> **v1.2 边界声明**:完整 schema 实例(`schema_v1.json` 样例)见 [`08-memory-distillation-pipeline.md` §七.2 Schema 稳定性保障](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档不重复 JSON 示例,仅保留 schema 结构设计要点。

> **v1.2 实现指引**:Phase 4 实操见 [`08-memory-distillation-pipeline.md` §八](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

### 6.1 训练样本结构

每条训练样本的完整结构设计要点:
- 顶层:`input` / `output` / `metadata`
- `input.text` + `input.context`(可选):原始文本块 + 上下文
- `output.extractions[]`:四元组列表,每条含 `subject` / `relation` / `object`(均含 `text` + `type` + `type_id`)+ `confidence` + `evidence_span` + `ccs_score`
- `output.schema_version`:对应 Phase 3 产出的 schema 版本号
- `metadata`:含 `source_doc` / `block_id` / `stratification`(memory/reasoning/mixed)/ `quality_flags[]`

> **v1.2 边界声明**:完整 JSON 实例与字段类型约束见 [`08-memory-distillation-pipeline.md` §八.2 训练样本组装](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档不重复 JSON 示例,仅保留训练数据结构的设计意图。

### 6.2 质量控制流水线（四道关卡）

**关卡 1：格式合规性检查**
```
- 所有字段非空
- entity_type 和 relation_type 必须在 schema 中存在
- 基数约束不被违反
- JSON 格式合法
```

**关卡 2：语义一致性检查**
```
- 用教师模型做"反向验证"：将提取的四元组输入教师，问"以下文本是否支持这个事实？"
- entailment 概率 ≥ 0.8 → 通过
- entailment 概率 < 0.8 → 标记为可疑，人工审核或丢弃
```

**关卡 3：去重与冲突检测**
```
- 全局实体消歧：同一实体在不同文档中的不同表述归一化
- 冲突检测：同一 (subject, relation) 对不同 object → 检查时间戳，保留最新版本
- 重复检测：语义相似度 ≥ 0.95 的四元组合并
```

**关卡 4：难度分级**
```
按 CCS 分数将训练样本分为三个难度等级：
- Easy (CCS < 0.2)：占 60%，用于训练初期
- Medium (0.2 ≤ CCS < 0.3)：占 30%，用于训练中期
- Hard (0.3 ≤ CCS < 0.4)：占 10%，用于训练后期
```

> **注意（v0.1 修订）**：memory 样本的 CCS = 0.3 × recon_sensitivity ≤ 0.3，hard 桶（0.3–0.4）对 memory 样本**永远为空**。这是预期的：memory 样本不需要 hard 训练。修订方案：
> - 选项 A：将 hard 桶改名为"边界记忆桶"，仅放入混入了推理信号的样本
> - 选项 B：将 hard 桶改用 ratio 重新定义：`hard = memory 样本中 CCS 处于 0.27~0.30 的 Top 10%`
> - 当前实现采用选项 B

### 6.3 数据规模估算

| 阶段 | 原始文本量 | 提取四元组数 | 通过质量控制 | 最终训练样本 |
|------|-----------|-------------|-------------|-------------|
| 单领域 MVP | 10 万条文本块 | ~50 万条四元组 | ~35 万条 | ~25 万条 |
| 多领域扩展 | 100 万条文本块 | ~500 万条四元组 | ~350 万条 | ~250 万条 |

## 7. Phase 5:小模型训练方案

> **v1.2 实现指引**:Phase 5 实操见 [`08-memory-distillation-pipeline.md` §九](../../agenticmemory_training/08-memory-distillation-pipeline.md)。本文档只保留设计原理。

### 7.1 基座模型选型

| 候选 | 参数量 | 优势 | 劣势 |
|------|--------|------|------|
| Qwen3-0.6B | 600M | 极轻量，推理速度快 | 结构化输出能力可能不足 |
| **Qwen3-0.6B（推荐默认）** | **0.6B** | **轻量、tokenizer 与探针完全对齐、与 AGENTS.md <1B 目标一致** | **极小容量，需更多 SFT 训练** |
| Qwen3-1.7B | 1.7B | 结构化提取能力强 | 容量提升边际递减 |
| Qwen2.5-1.5B（v0.1 原始）| 1.5B | 结构化提取能力的最低阈值 | 与新探针架构 tokenizer 不对齐 |

**推荐：Qwen3-0.6B（默认）/ Qwen3-1.7B（可选增强）**。

理由：
1. **0.6B 作为"记忆引擎"**：职责单一（结构化提取 + 不需推理），0.6B 的能力足够；与项目顶层"<1B"目标一致
2. **1.7B 作为"高保真版"**：当 schema 复杂（>100 关系类型）或样本难度高（大量 CCS ≥ 0.3）时升级
3. **v0.1 推荐的 1.5B** 因 tokenizer 与新探针架构不兼容而被替换

**关键约束：训练目标必须与探针 tokenizer 对齐**——违反会导致测试阶段概率分布不可比。

### 7.2 三阶段训练策略

**阶段 1：结构化输出格式对齐（1 epoch）**

```
目标：让模型学会输出 JSON 格式的结构化记忆
数据：全量训练集（25 万条）
训练方式：
  - 输入：text + "请以JSON格式提取所有事实性知识"
  - 输出：标准 JSON 格式的四元组列表
  - 损失函数：标准 next-token prediction
  - 学习率：2e-5，cosine schedule
  - 关键：此阶段不区分记忆/推理，只训练格式遵从能力
```

**阶段 2：Schema 约束内化（2 epochs）**

```
目标：让模型学会使用 schema 中定义的类型体系
数据：全量训练集，但 prompt 中注入 schema 信息
训练方式：
  - 输入：text + schema 摘要（实体类型列表 + 关系类型列表）
  - 输出：使用 schema 中定义的类型标注的结构化四元组
  - 关键创新：将 schema 作为 "system prompt" 的一部分注入
  - 学习率：1e-5（降低以避免遗忘阶段 1 的能力）
```

**阶段 3：难度感知精调（1 epoch）**

```
目标：让模型对不同复杂度的知识有差异化的提取能力
数据：仅使用 Easy + Medium 样本（按 CCS 分级）
训练方式：
  - Easy 样本：标准提取
  - Medium 样本：添加 CoT 提示 "请逐步分析文本中的事实"
  - 关键：不使用 Hard 样本（CCS ≥ 0.3 的属于推理层，不应由记忆模型处理）
  - 学习率：5e-6
```

### 7.3 蒸馏对齐（可选增强）

在三阶段训练完成后，可用教师模型做一轮蒸馏对齐：

```
蒸馏方式：结构化输出蒸馏（非 logit 蒸馏）
  - 教师模型对同一文本块重新提取
  - 计算学生输出与教师输出的结构相似度（图编辑距离）
  - 用结构相似度作为奖励信号做 DPO/RLHF
  - 这比传统 logit 蒸馏对 Capacity Gap 更鲁棒
```

```
触发条件：
  - 新领域语料接入
  - 连续 2 周出现 > 10% 的"schema 外"关系类型
  - 人工抽检发现 schema 缺失

更新流程：
  1. 收集新的四元组（schema 外的）
  2. 对新关系/实体做聚类 + LLM 概念化
  3. 与现有 schema 做合并检查
  4. 生成 schema v(n+1)
  5. 用新 schema 重新标注增量数据
  6. 增量训练小模型（仅 0.5 epoch）
```

## 9. 风险分析与缓解措施

#### 风险 1：教师模型的提取偏差向下游传导

**风险描述**：教师模型（V4 Flash）的 OpenIE 提取本身存在错误（幻觉、遗漏、关系错误），这些错误会通过 Capacity Gap 分层传导到训练集中，被小模型"学习"并固化。

**量化评估**：根据 CycleOIE 的研究，GPT-3.5 标注的 OpenIE 数据在人工校验下约有 12-18% 的错误率。 V4 Flash 作为更强的模型，预估错误率在 8-12%。

**缓解措施**：
- **多教师交叉验证**：用两个不同的教师模型（如 V4 Flash + Qwen2.5-72B）同时提取，仅保留两者交集
- **反向验证**：对每条四元组，用教师模型做 NLI 验证（"原文是否支持这个事实？"），entailment < 0.8 的丢弃
- **置信度加权**：教师置信度 < 0.7 的四元组降权处理

#### 风险 2：探针模型的领域盲区导致系统性误分

**风险描述**：即使做了领域自适应校准，探针模型仍可能在某些子领域存在盲区。例如，法律文本中的"管辖权"类关系，探针可能完全无法提取，但这些实际上是显式事实（记忆类），会被错误归入推理层。

**缓解措施**：
- **分层校准**：不仅做领域级校准，还做子领域级校准（按文档类别分组校准）
- **重构敏感度兜底**：对被归入推理层的样本，用重构敏感度测试做二次验证
- **人工抽检**：对推理层中教师置信度 > 0.9 的样本，随机抽检 5% 做人工验证

#### 风险 3：Schema 涌现的不稳定性

**风险描述**：聚类结果对超参数敏感，不同随机种子可能产出不同的 schema。LLM 概念化也存在随机性。这导致 schema 在不同运行之间不一致。

**缓解措施**：
- **多次运行取共识**：对聚类做 3 次不同随机种子，取交集作为"稳定簇"
- **LLM 概念化温度 = 0**：消除随机性
- **Schema 版本化**：每次 schema 更新都保留版本号，支持回溯

#### 风险 4：小模型对 Schema 的"硬记忆"而非"软理解"

**风险描述**：小模型可能只是死记硬背了 schema 中的类型名称，而非真正理解了类型的语义边界。当遇到 schema 中未覆盖的新实体/关系时，模型可能强行套用最接近的类型，导致错误标注。

**缓解措施**：
- **训练时注入类型定义**：不仅告诉模型"这是 Person 类型"，还告诉它"Person 的定义是：具有姓名的自然人个体"
- **负样本训练**：10% 的训练样本故意使用错误的类型标注，让模型学会拒绝不匹配的标注
- **"Unknown" 类型兜底**：在 schema 中保留一个 "Unknown" 类型，模型在不确定时应输出 Unknown 而非强行分类

#### 风险 5：错误级联——分层错误在训练中被放大

**风险描述**：如果某条推理类知识被错误标注为记忆类并进入训练集，小模型会"学会"直接从文本中提取需要推理才能获得的信息。在部署时，模型会对需要推理的问题给出看似合理但实际错误的答案，且这种错误很难被 schema 校验器检测到。

**缓解措施**：
- **CCS 连续谱系 + 置信度门控**：CCS 在 0.3-0.7 之间的样本不进入训练集，而是进入"人工审核队列"
- **回溯验证**：训练完成后，用训练好的小模型在验证集上测试。如果某条"记忆类"样本的提取结果与教师差异过大，触发"重新标注"
- **对抗样本检测**：构造需要推理才能回答的问题，测试小模型是否会"越界"给出推理类答案。如果会，说明训练集中混入了推理类数据

#### 风险 6：时序漂移——知识的时间敏感性

**风险描述**：某些四元组在提取时是"记忆类"（如"2025年CEO是张三"），但随着时间推移可能变为需要推理才能确认的信息。

**缓解措施**：
- 为每条四元组附加时间戳和有效期元数据
- 定期（如每季度）对"时间敏感"类关系触发重新分层
- 在 schema 中标注哪些关系类型是"时间敏感的"（如"任职于"、"股价"）

#### 风险 7（v0.1 新增）：冷启动校准失效

**风险描述**：领域自适应基线校准（§2.2）使用 5000-10000 条样本，若该样本不能代表目标领域真实分布（例如抽样偏差），探针基线提取能力评估会偏乐观/悲观。

**缓解措施**：
- **多样性采样**：5000 条样本必须覆盖目标领域的**所有子主题**
- **校准验证**：校准完成后用 200 条**人工标注**测试集验证探针 F1 ≥ 0.5
- **增量校准**：每 10K chunk 后重做一次微校准

#### 风险 8（v0.1 新增）：灰色地带样本流失

**风险描述**：CCS 在 0.3-0.7 之间的灰色样本被强制不进训练，若该区间集中了大量优质记忆样本，会导致训练数据不足。

**量化预警**：若灰色样本占比 > 30%，触发人工审核队列扩容；若 > 50%，重新评估阈值合理性。

**缓解措施**：
- **人工审核抽样**：每周从灰色样本中抽样 200 条人工标注，统计其中"应进入记忆类"的比例
- **比例监控**：灰色样本占比 > 30% 时触发阈值重新校准
- **优先级队列**：人工审核队列按"教师置信度高 + CCS 接近 0.3"的优先级排序

## 11. 核心创新点总结

1. **Capacity Gap 作为分层判据的理论落地**：不是简单的"大模型 vs 小模型"对比，而是利用苹果蒸馏扩展定律揭示的"学习能力差距"本质，结合重构敏感度和结构化提取瓶颈做多维度验证。

2. **Schema 从数据中涌现而非人工预定义**：借鉴 AutoSchemaKG 的 Extract-Define-Canonicalize 范式，但将其与 Capacity Gap 分层机制耦合——只有记忆层的四元组参与 schema 构建，确保涌现出的 schema 反映的是"可压缩的静态知识结构"。

3. **结构化输出蒸馏而非 logit 蒸馏**：规避了 Capacity Gap 诅咒对传统蒸馏的影响，小模型学习的是离散的语义结构而非连续的概率分布。

4. **连续谱系替代硬性二分**：CCS 分数机制确保了灰色地带不会被粗暴归类，混合层的引入避免了信息损失。

5. **崩溃对照组（L3）排除 trivial 样本**（v0.1 新增）：通过 0.6B 探针区分"非平凡记忆"与"trivial 事实"，避免训练集被简单样本污染。

6. **Tokenizer 对齐硬约束**（v0.1 新增）：跨系列 tokenizer 比较会被分词噪声污染概率分布，所有探针必须与教师 tokenizer 对齐（或同系列内对齐）。

这套方案的最终愿景是：**让一个小模型成为高效的"记忆引擎"——它不思考、不推理，只负责从文本中快速、准确地提取和输出结构化事实，而将推理任务留给更大的模型。** 这正是 System 1 / System 2 解耦在工程上的精确映射。
